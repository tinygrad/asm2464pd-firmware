The audit/RE conflated usb4_connect_u4 (the small a3f5 INNER RMW) with the connect ENTRY; the real entry/wrapper is bank0_8a89, a large function with a C80A.6-servicing wait loop, CC10 mailbox arms (0x27 then 0x13), e7ae, the 0x07ED suppress handshake, and a cd10 tail.
- E764 is NOT a PCIe-only / boot-only register. USB4_RE.md/USB4_AUDIT_PLAN.md map E764 only as 'PCIe PHY link-training enable' (d996/cdc6) and as pcie_power_on's hardcoded one-shot 0x1C. E764 bit4 is the USB4 LINK-MODE-ENABLE, RMW'd by bank0_8a89 on the dynamic lane-bringup path. The literal E764=0x1C in handmade pcie_power_on (main.c:95) is a fabrication — stock never writes E764 as a literal — and it clobbers the CM-owned link-mode nibble.
- The prior verdict 'FULL usb4_connect_u4 tail (a48c-a516) REGRESSED E302 to mode0; e7ae C006/C00E PHY-lock wait disturbs training' (MEMORY + usb4.h/sb.h comments) is INVALID. It was measured with bank0_8a89 never run, so link-mode (E764.4/E751) was never armed and the e7ae PHY-lock wait had nothing to lock onto. The e7ae wait is correct stock behavior, gated on 0x0AF1.4 inside the tail. Re-test the full tail ONLY after wiring bank0_8a89 + the INT0 link-event ISR.
- The connect is NOT triggered by the PD/VDM Enter_USB Accept path. handmade's design of calling usb4_connect_u4() synchronously from the VDM/Enter_USB Accept handler (vdm.h:287) is structurally wrong: stock connects DYNAMICALLY from the INT0 link-event ISR (0e5b -> e94d/e952 -> c9a8 -> bank0_8a89), re-driven per host link-event. usb4_connect_u4 is called from THREE sites (Enter_USB data-msg a17f, VDM cmd4/5 9c0b, and inside bank0_8a89 8d49) — a single static call cannot reproduce the iterative handshake. (The Enter_USB DATA-message tail itself IS faithful in handmade; the gap is the VDM path + the INT0 state machine.)
- 0x0AF1 is a DYNAMIC connect-time gate, not a static boot constant. The audit treats bank0_92c5 seeding 0x0AF1=0 as 'matches stock' and final, but BOTH usb4_connect_u4@a3f5 and c9a8 require 0x0AF1.0 SET before the connect inner body runs. Seeding it 0 and never setting it makes handmade's connect inner-body a permanent no-op.
- cc_state_full_reset@0xD676 is NOT a print-only diagnostic. The handmade comment / prior audit claim 'a single banked uart_puts, NOT a HW register op' is a truncation artifact and is provably FALSE: d676 does CC32 RMW, E7FA=0x0F, CC88[2:0]=4 + CC89 go/poll/ack, CC31 clear — a real CC-controller full reset (Type-C Error-Recovery).
- cc_cc23_reinit_event@0xE3D8 is NOT just 0x07E8=0;0x0B2F=1. The full body calls pcie_downstream_link_bringup@0x3578 (the full eGPU downstream PCIe LTSSM/PERST/lane-width bring-up — a BANK0, fully-decompilable function, NOT 'deep/banked CM-owned' as pd.h claims) plus bank0_e3b7(3) and bank0_d810 (CC17=4/2/1). Omitting it is a high-severity functional gap.
- USB4_AUDIT_PLAN.md I13 ('a066 connect/disconnect edge: drop SB[0x66]/[0x9E] writes; fabricated') is PROVABLY WRONG. a066's SB[0x66] (96cd), SB[0x9E] (96e3) and SB[0x26] (96ec) reads are REAL, distinct, load-bearing event branches (Lane Bonded / CL0 / Abr2 / Bnd Fail / Disable / [Pend Int]). They must be KEPT and correctly mapped, not dropped.
- handmade sb_router.h mis-maps the a066 back-half registers: it conflates SB[0x26] (read at a156, the [Pend Int]->a5d8 branch) with SB[0x9E] (read at a16a/a1c7, the L0/L1:CL0 branches), losing the entire SB[0x26].1 -> a5d8 device->host sideband responder branch. The [===SB Con===] edge also clears the WRONG register: handmade does SB[0x66]&=0xFD; stock increments SB[0x2C] and sets SB[0x2D].0/clears SB[0x2D].1.
- handmade sb_con_consequence (the dea1 transcription) is INCOMPLETE, not byte-faithful: it drops 0x06EC=1 (which arms the per-iteration cb10 SB advance) and the db7a call (CA60/E7FA/EB62 tunnel-route arm). The comment 'if (page1 0x0109 & 1) return; else SB[0x28]|=0x40' is wrong — dea1 does NOT early-return on 0x0109; it always proceeds to the SB[0x28]/[0x29] arming, e80a(0,0x15,2), 0x06EC=1 and db7a.
- handmade sb_chan_prelude (edd9) reads SB[0x09] and the comment labels it 'SB[0x09]' — WRONG. edd9 reads PAGE-1 XDATA 0x0109 (lane-bond-done) via 9779 and, if bit0, runs a real PHY/transport re-arm (98b7/973d/9789=E716/eb62=0x06ED/98ec=0x0758). Different page, different semantics.
- usb4_irq.h comment claiming SB 0x94..0x99 are HW-latched is WRONG: b230 b307-b313 writes the SB 0x94..0x99 PHY-RX descriptor explicitly. handmade's sb_lane_flip_init and sb_rom_descriptor_load omit the b307-b39e and b83b-b8d8 tails (C801.4/C809.3 enables, SB[0xC9] connect-detect arm, 0x06F1 active-port latch, CCD8/CCDA/CCDB=200/CCD9 strobe) that are load-bearing for the C80A.5 service path.
- The CONTROL jump-table layout in pd_dispatch.h comments is wrong: there is NO key 0x0D (real Soft_Reset hits the 0x8706 default NAK, so handmade's dedicated pd_ctrl_soft_reset is a from-scratch invention, not a stock mirror); key 0x0E @0x869A is Data_Reset (string [Data_Reset]@0x23BB), NOT Soft_Reset; key 0x08 @0x8686 is Get_Sink_Cap (->0xB624); key 0x0F is Data_Reset_Complete; key 0x10 is Not_Supported.
- cm-routerop is NOT purely interrupt-driven: there is a SECOND, super-loop-driven router-op channel over the CE88/CE89 SB-transport mailbox (FUN_CODE_180d -> 3cb8 -> 38d4 -> func_0def key 0x12 -> bank1_a327) that the prior audit/MEMORY never identified. func_0def appears in TWO places: c0c2 (EA80 generation opcodes 0xe0-0xe8) and 0x3915 (the inbound message-state 0x0002 dispatcher). The handmade EC04=1-only stub for EC06.0 is a functional regression — c0a5 IS fully recoverable/decompiled.
- The 'host does NO PD / device purely reactive' framing is wrong for the SB/router-op layer: the device runs an ACTIVE request/RESPONSE protocol — it reads host sideband requests (CE88/EA80 mailboxes) and BUILDS+SENDS replies (a327/c0a5 -> FUN_CODE_425f / C805|=0x02). It is now PROVABLE from code that the host DOES need CM router-op responses (both the EC06.0/c0a5 config-space path and the CE88/a327 descriptor/lane-bond path are wired in stock; handmade implements neither). This refutes [[project_handmade_usb4_impl]]'s central claim.
- init_sys_flags@0x4BE6 omissions: handmade's usb4_irq_arm skips the 0x07F0..0x07F5={0x24,4,0x17,0x85,0,0} policy-timer seeds AND bank0_cb37 (92xx PIPE link-partner config), both of which 4BE6 runs before INT arming.
