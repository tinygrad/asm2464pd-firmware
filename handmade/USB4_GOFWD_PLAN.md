# USB4 go-forward plan (static-vs-stock)

## Immediate blocker verdict
STATIC-FIXABLE (category A) on two independent, code-determined axes; only the precise host timeout VALUE and final HW confirmation are category B (and neither blocks the fixes).

The "host HARD_RESETs handmade within ~ms after [===SB Con===]" blocker has TWO root causes, both fully visible in fw_tinygrad.bin (no dynamic stock trace needed to settle the WHAT/WHY):

(1) PD-LEVEL NAK (Thread "disc-svids-hardreset"): On stock's success path the host sends Discover_SVIDs RIGHT AFTER [===SB Con===] (memory reference_stock_usb4_enum_sequence: [SB Con][SB P03] -> [VDM][Discover_SIDs] -> [VDM][Discover_Modes][ConnRout][SB P04]). Stock's vdm_build_discover_sids_resp@0xDDAD ACKs SVID 0xFF00 (disasm 0xddb0 CPL A / 0xddb1 ORL A,R2 / 0xddb2 JNZ NAK => (~A|R2)==0 == one byte 0xFF, other 0x00). handmade/src/vdm.h:147 instead requires SVID==0xFFFF (`rx_svid_lo==0xFF && rx_svid_hi==0xFF`), so it NAKs the very VDM stock ACKs. The Discover_SVIDs request carries the PD SID 0xFF00 (lo=0x00, hi=0xFF), so handmade's guard is FALSE and falls through to vdm_nak. 0x07BC stays 0 on the normal USB4 path (verified: pd_handle_enter_usb@0xA036 / usb4_connect_decide@0xA0A7 set only 0x07BB/0x07BA; only pd_cc_attach_term_setup@0xBAA0 on the host-command 0x07000 path writes it), so handmade IS in the discovery-ACK dispatch and the wrong guard is exactly what NAKs. This is a one-line fix.

(2) FSM-ARM + LOOP-SPEED (Thread "post-connect timing"): Stock pre-arms the lane-bond FSM (0x06ED=3) INSIDE the C80A.5 ISR: a066 -> dea1 (sets 0x06EC=1) -> db7a, whose decompiled tail is literally `eb62(0,3); 98ec()` (eb62 disasm: MOV DPTR,#0x6ed; MOVX => 0x06ED=3). So on ISR return the FSM is state-3 and stock's TIGHT, delay-free, UART-free super-loop (main_boot_and_superloop@0x2FB4: `if((0x09F9&0x83)&&0x06EC){EA=0; cb10(); ...}`) runs cb10->e672->cm_conn_routing_setup ([ConnRout]) within microseconds. handmade DROPS eb62(0,3) (sb_router.h:173-174 explicit defer comment), moving the arm to the slow super-loop's `if(0x06ED==0)` first-arm (main.c:794-799), AND its super-loop runs a 60000-NOP delay (main.c:674) + ~70 UART field-prints (main.c:679-778) + a bank0_8a89 drive with EX1 masked (main.c:815-844) BEFORE/AROUND the FSM pump (main.c:788) — orders of magnitude slower than stock. So handmade is mid-diagnostic-dump when the host expects [ConnRout]-class progress within its CM timer.

These two reproduce stock's behavior from the CODE ALONE. The ONLY category-B residue: (a) the exact numeric host post-connect/CM timeout (a TUNING datum — how MUCH to tighten — not a blocker; the fixes are strictly correct regardless), and (b) HW confirmation that timing+the SVID-NAK are the SOLE post-connect blockers (no second in-ISR status bit the host polls). Implement the static fixes now; the stock hooks only validate margin and rule out a second cause.
